## 1. 使用说明

本文把 Sprint 2 User Story 拆成前端、后端、数据库、安全、测试和文档 Task。Task 不单独代表用户价值；只有所属 User Story 的全部验收标准通过，Story 才能完成。

任务状态：

- `Draft`：内容仍需评审或估算。
- `Blocked`：拆分已可评审，但尚未满足开发门禁。
- `Ready`：依赖与验收口径已确认，可以领取。
- `In Progress`、`Review`、`Done`：进入开发后的执行状态。

复杂度仅用于相对比较，不替代团队估算：`S` 为局部、低风险；`M` 为跨多个类/组件；`L` 为跨层或高安全风险。所有复杂度和负责人均在 Sprint Planning 确认。

## 10. Task Definition of Ready

单个实现 Task 转为 `Ready` 前必须满足：

- 所属 User Story 为 Ready，验收标准无待决业务歧义。
- 依赖 Task 已完成或有稳定可用契约。
- 数据库、API、Cookie、CSRF、角色或错误码变化已明确评审人。
- 已识别需要新增/更新的测试用例编号。
- 不需要真实生产凭证才能开发和验证。
- 复杂度与负责人已由团队确认，工作量适合在 1 至 2 个工作日内完成；超出则继续拆分。

## 11. Task Definition of Done

单个实现 Task 只有同时满足以下条件才可标记 `Done`：

- 实现满足 Task 工作内容及所属 Story 的相关验收标准。
- 自动化测试已新增或更新，针对性检查通过。
- 未修改 V1 迁移，未提交真实凭证、依赖目录、构建产物或临时文件。
- 日志、异常、响应和测试输出不包含密码、摘要、会话标识或 Cookie。
- 文档与实际 API、配置、错误码和命令保持一致。
- 变更已完成代码评审；公共 API、迁移和安全配置由指定评审人确认。
