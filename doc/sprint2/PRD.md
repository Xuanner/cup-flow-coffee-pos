| 项目 | 内容 |

## 1. 文档目的

本文定义 Sprint 2 登录体系的产品目标、范围、业务规则、安全基线和验收口径。Sprint 2 只建立后续业务模块共同依赖的身份与权限基础，不实现 POS、订单、商品或看板业务功能。

本版已于 2026-08-24 完成产品、研发和测试门禁确认。开发必须遵循本文、`FEATURES.md`、`USER_STORIES.md`、`API_CONTRACT.md`、`TEST_STRATEGY.md` 和 `TASKS.md`；需求变化先更新基线再修改实现。

## 2. 背景与问题

Sprint 1 已建立 React、Java、PostgreSQL、统一 API、错误处理、路由和账号数据结构等工程基础，但当前登录页与业务路由仍是无鉴权占位实现，任何访问者都可以直接打开模块入口。

Sprint 2 需要解决：

- 员工无法使用预置账号建立可信登录态。
- 刷新页面、打开新标签页和会话过期时缺少一致行为。
- 收银员与管理员的页面入口和后端接口尚未执行角色校验。
- 退出、认证失败和越权行为缺少安全日志与统一反馈。
- 后续 Sprint 尚无可复用的当前用户与权限上下文。

## 3. Sprint 目标

1. 启用的预置员工账号可以通过账号和密码安全登录、查询当前登录身份并退出。
2. 登录态可在同一浏览器会话内刷新恢复，并在空闲、绝对时限、退出或账号停用后失效。
3. 收银员与管理员只能看到并访问各自有权使用的页面与接口。
4. 登录失败、未登录、会话过期和无权限使用一致且不泄露敏感信息的反馈。
5. 登录成功、失败、退出和权限拒绝形成可追踪且不含凭证的安全记录。
6. 为 Sprint 3 至 Sprint 6 提供稳定的认证与角色校验入口。

## 4. 非目标

以下内容不进入 Sprint 2：

- 员工账号新增、编辑、删除、停用操作界面。
- 注册、邀请、忘记密码、自助重置密码、修改密码和首次登录强制改密。
- 手机号、邮箱、短信验证码、扫码登录、生物识别、单点登录和多因素认证。
- 自定义角色、权限配置界面和按钮级细粒度授权模型。
- 多门店、总部组织、跨店账号、排班和考勤。
- 管理员强制其他设备下线、查看在线设备或限制单账号同时登录数。
- 记住登录、长期刷新令牌和关闭浏览器后自动恢复会话。
- 完整安全运营平台、验证码和复杂风控策略。
- POS、订单、商品、看板的业务数据与操作；Sprint 2 只保护其占位入口或后续接口边界。

## 5. 目标用户与角色

| 角色 | Sprint 2 核心诉求 | 可访问入口 |
| --- | --- | --- |
| 收银员 `CASHIER` | 快速登录并进入日常收银工作区 | POS、订单 |
| 管理员 `ADMIN` | 登录后进入管理工作区，并可切换到全部第一阶段模块 | POS、订单、商品、经营看板 |

业务规则：

- `ADMIN` 包含 `CASHIER` 的第一阶段业务权限，不要求同一账号重复分配两个角色。
- 一个账号若存在多个有效角色，按权限并集处理；Sprint 2 不提供角色切换器。
- 系统状态和组件预览属于开发诊断入口，不作为生产业务菜单或角色权限承诺。

## 6. 核心用户旅程

### 6.1 成功登录

1. 未登录员工访问系统或受保护地址。
2. 系统展示登录页；若来自受保护地址，安全记录站内目标地址。
3. 员工输入账号和密码并提交。
4. 系统校验字段、账号状态、密码和登录频率。
5. 成功后建立服务端可撤销会话，返回当前用户的必要展示信息和角色。
6. 若原目标地址有权访问则返回该地址，否则收银员进入 POS、管理员进入经营看板。

### 6.2 登录失败

1. 账号不存在、密码错误或账号停用时均不建立登录态。
2. 页面统一提示“账号或密码错误，或账号不可用”，不说明账号是否存在或停用。
3. 密码输入被清空，账号输入保留，焦点回到密码字段。
4. 达到频率限制时提示稍后重试，不锁死账号，也不提供账号状态线索。

### 6.3 恢复与过期

1. 页面刷新或同一浏览器会话打开新标签页时，前端向后端确认当前会话。
2. 确认期间显示应用级加载状态，不短暂渲染未授权页面。
3. 会话有效则恢复用户和角色；无效或过期则清除前端身份状态并进入登录页。
4. 因过期退出时显示“登录已过期，请重新登录”；系统不承诺保存未提交表单或交易草稿。

### 6.4 主动退出

1. 已登录员工从全局账号区域选择退出。
2. 系统使服务端当前会话失效并清除浏览器会话凭证。
3. 页面返回登录页；后退、刷新或重放旧凭证均不能恢复原会话。

## 7. 产品需求

### 7.1 身份认证

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2-AUTH-01 | 员工可使用账号和密码登录；账号输入去除首尾空白，密码保持原值校验 | Must |
| S2-AUTH-02 | 仅状态为 `ACTIVE` 且密码正确的账号可建立登录态 | Must |
| S2-AUTH-03 | 账号不存在、密码错误或停用账号使用统一失败反馈 | Must |
| S2-AUTH-04 | 登录提交期间防止重复提交，并提供明确的加载、失败和恢复动作 | Must |
| S2-AUTH-05 | 已登录用户访问登录页时进入其默认有权页面 | Must |

### 7.2 会话生命周期

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2-SESSION-01 | 登录态由服务端验证并可撤销；浏览器脚本不得读取会话凭证 | Must |
| S2-SESSION-02 | 同一浏览器会话内刷新和新标签页可恢复当前身份 | Must |
| S2-SESSION-03 | 会话具备空闲过期和绝对过期机制；每次受保护请求均校验有效性 | Must |
| S2-SESSION-04 | 员工可主动退出，退出后原会话不可继续访问受保护资源 | Must |
| S2-SESSION-05 | 账号在会话期间变为停用时，下一次受保护请求使该会话失效 | Must |
| S2-SESSION-06 | 会话过期与普通未登录使用相同安全边界，但前端向用户区分提示 | Must |

### 7.3 角色与访问控制

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2-AUTHZ-01 | 所有业务页面默认受保护；未登录访问时进入登录页 | Must |
| S2-AUTHZ-02 | 菜单只展示当前角色可访问的业务模块 | Must |
| S2-AUTHZ-03 | 已登录但无权限访问页面时展示 403，不把越权伪装成未登录 | Must |
| S2-AUTHZ-04 | 后端独立校验每个受保护接口的登录态与角色，不依赖前端菜单或路由 | Must |
| S2-AUTHZ-05 | 认证接口之外的业务接口采用默认拒绝；显式公开接口须列入白名单 | Must |
| S2-AUTHZ-06 | 登录后仅接受站内且有权限的返回地址，拒绝外部跳转和开放重定向 | Must |

### 7.4 初始化账号

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2-ACCOUNT-01 | 非生产演示/测试环境至少提供一个收银员账号和一个管理员账号 | Must |
| S2-ACCOUNT-02 | 初始化过程只保存强密码摘要，不在仓库、迁移、日志或接口中保存/返回明文密码 | Must |
| S2-ACCOUNT-03 | 生产环境不得使用仓库内共享默认密码；初始凭证通过部署环境的受控渠道提供 | Must |
| S2-ACCOUNT-04 | 重复部署或迁移不得重复创建账号，也不得意外覆盖已有密码与状态 | Must |

### 7.5 安全、审计与错误处理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2-SEC-01 | 密码使用当前批准的自适应单向哈希算法与独立随机盐保存 | Must |
| S2-SEC-02 | 登录接口具备不泄露账号存在性的频率限制；触发后返回可恢复提示 | Must |
| S2-SEC-03 | 使用 Cookie 会话时启用 `HttpOnly`、适当的 `SameSite`、生产环境 `Secure` 与跨站请求防护 | Must |
| S2-SEC-04 | 日志和响应不得包含密码、密码摘要、会话标识、Cookie 或完整凭证 | Must |
| S2-SEC-05 | 记录登录成功、登录失败、退出、会话失效和权限拒绝的时间、结果、必要主体/请求上下文及 `traceId` | Must |
| S2-SEC-06 | 认证失败返回 401、权限不足返回 403、频率受限返回 429，并保持统一 API 响应结构 | Must |

## 9. 页面与交互要求

### 9.1 登录页

- 包含账号、密码、显示/隐藏密码和登录按钮。
- 账号、密码为空时在客户端给出字段级错误，并将焦点移到首个错误字段。
- 密码默认隐藏；显示/隐藏控件可通过键盘操作且具有可理解的无障碍名称。
- 提交期间按钮显示加载状态，字段和重复提交受到控制。
- 失败提示可被辅助技术感知，不使用颜色作为唯一信息载体。
- 不提供“记住我”“忘记密码”或注册入口。

### 9.2 已登录全局区域

- 展示员工显示名称与角色名称，不展示账号敏感详情。
- 提供键盘和触屏可操作的退出入口。
- 导航依据角色过滤；直接输入无权地址仍由路由与后端分别拦截。

### 9.3 全局认证状态

- 首次确认会话时展示加载状态，避免未授权内容闪现。
- 会话过期后展示一次性提示并进入登录页。
- 403 页面说明“当前账号无权访问”，提供返回默认页面的动作。
- 网络或服务异常不能误报为账号密码错误；保留账号输入并允许重试。

## 10. 会话与安全基线

| 项目 | v1.0 决定 | 理由 |
| --- | --- | --- |
| 会话形态 | 服务端持久化的不透明会话 ID + HttpOnly Cookie | 支持立即退出、停用账号失效和浏览器脚本隔离凭证 |
| 空闲时限 | 30 分钟 | 降低共享收银设备离席风险，同时避免高频营业中反复登录 |
| 绝对时限 | 8 小时 | 与单个工作班次相近，限制长期会话风险 |
| 浏览器关闭 | 会话 Cookie 结束；服务端记录按自身过期时间清理 | 不引入“记住登录” |
| 初始限流 | 同一来源与账号标识组合 15 分钟内连续失败 5 次后短暂限制 | 降低暴力尝试，同时避免永久锁号且不泄露账号存在性 |
| 管理员默认页 | `/dashboard` | 符合“管理端”语义；后续业务页尚未实现时允许显示受保护占位页 |
| 收银员默认页 | `/pos` | 对齐最高频工作入口 |

以上参数已冻结；变更必须走需求变更评审，并同步更新 API、测试和 Task 基线。

## 11. 非功能需求

### 11.1 安全

- 所有生产认证流量必须通过 HTTPS。
- 会话 ID 具有足够随机性；登录成功时重新生成，防止会话固定。
- 密码比较、未知账号和停用账号路径避免明显可利用的时序差异。
- 退出操作必须具备跨站请求防护，不得通过可被第三方页面触发的简单 GET 完成。
- 返回地址只允许规范化后的站内路径。

### 11.2 性能与可用性

- 正常网络与目标容量下，登录、当前身份查询和退出接口 P95 目标不超过 500ms，不含前端资源加载时间。
- 支持第一阶段 5 个并发员工的稳定使用。
- 认证服务异常时不放行受保护资源，页面给出可重试提示和 `traceId`。

### 11.3 可测试性与可维护性

- 密码校验、会话状态、角色判定和返回地址校验具备自动化单元测试。
- 登录、退出、过期、停用和 401/403/429 具备后端接口测试。
- 受保护路由、菜单过滤、会话恢复和错误反馈具备前端组件/路由测试。
- 至少一条端到端测试覆盖“登录—访问授权页面—退出—旧会话失效”。
- 测试日志和失败快照不得打印凭证。

## 13. 风险与控制

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 只隐藏前端菜单 | 直接调用接口可越权 | 后端默认拒绝并执行角色校验；加入反向权限测试 |
| 凭证保存在可被脚本读取的位置 | XSS 可窃取登录态 | 使用 HttpOnly Cookie，不把会话凭证写入 localStorage/sessionStorage |
| 登录提示区分账号状态 | 枚举员工账号 | 不存在、密码错误、停用统一反馈与相近处理路径 |
| 共享设备离席未退出 | 他人继承权限 | 空闲/绝对过期、明显退出入口；自动锁屏留待后续评估 |
| 初始化账号泄露默认密码 | 生产环境被直接登录 | 密码摘要入库，生产明文仅由受控部署渠道注入 |
| 会话失效导致未提交工作丢失 | 后续交易体验受损 | Sprint 2 明确不承诺草稿保留；Sprint 3 另行设计交易恢复 |
| 认证依赖不可用时错误放行 | 敏感数据暴露 | 失败关闭，服务异常返回统一错误而不是绕过鉴权 |
