本文档只覆盖 Sprint 2 登录体系。优先级均为 Must；故事点由团队在需求评审通过后估算。每条验收标准均要求前后端独立执行安全边界，不能以页面隐藏代替服务端校验。

## 1. 安全登录

### US-S2-AUTH-01 员工使用账号密码登录（Must）

**用户故事：** 作为门店员工，我希望使用账号和密码登录，以便进入自己有权使用的工作区。

**所属 Feature：** F-S2-01 安全登录。

**关联需求：** AUTH-01、AUTH-03、S2-AUTH-01、S2-AUTH-02、S2-AUTH-04、S2-AUTH-05。

**前置条件：** 测试环境存在启用的收银员和管理员账号。

**验收标准：**

- 登录页包含账号、密码、显示/隐藏密码与登录按钮，密码默认隐藏。
- 账号或密码为空时不发送登录请求，显示字段级错误并聚焦首个错误字段。
- 账号校验前去除首尾空白；密码不被去空白、改大小写或其他规范化。
- 启用且密码正确的收银员可登录并进入 `/pos`。
- 启用且密码正确的管理员可登录并进入 `/dashboard`。
- 若登录前访问了站内受保护地址，登录成功且角色有权时返回该地址；外部、畸形或无权地址不被采用。
- 提交期间显示加载状态并阻止同一表单重复提交。
- 登录成功后生成新的服务端会话，响应不返回密码、密码摘要或可由前端脚本持久化的会话凭证。
- 已登录用户访问 `/login` 时进入其默认有权页面。

### US-S2-AUTH-02 安全处理登录失败（Must）

**用户故事：** 作为输入有误或账号不可用的员工，我希望得到清楚且可恢复的提示，以便重试，同时不暴露账号安全信息。

**所属 Feature：** F-S2-01 安全登录。

**关联需求：** AUTH-03、SYS-01、S2-AUTH-03、S2-AUTH-04、S2-SEC-02、S2-SEC-06。

**验收标准：**

- 账号不存在、密码错误和账号停用均不建立登录态，并使用相同 HTTP/业务错误码和用户提示。
- 统一提示不说明账号是否存在、是否停用或哪一项凭证错误。
- 失败后保留账号、清空密码并把焦点移回密码字段。
- 网络失败、服务异常与凭证错误使用不同提示；网络或服务恢复后可直接重试。
- 连续失败达到评审确认的阈值后返回 429 和“尝试次数过多，请稍后再试”等可恢复提示。
- 限流判断与响应不暴露账号是否存在，限制到期后无需管理员操作即可重试。
- 错误响应保持统一 API 结构并包含 `traceId`，不包含堆栈、密码、密码摘要、Cookie 或会话标识。

### US-S2-SEC-01 安全保存和校验密码（Must）

**用户故事：** 作为门店员工，我希望系统安全保存和校验我的密码，以降低账号数据泄露后的风险。

**所属 Feature：** F-S2-01 安全登录。

**关联需求：** S2-SEC-01、S2-SEC-04。

**验收标准：**

- 数据库只保存经批准的自适应单向密码哈希，不保存明文、可逆密文或独立明文盐字段。
- 相同明文密码生成的摘要不要求相同，密码校验使用算法提供的安全验证方式。
- 认证代码、异常、响应和日志不输出明文密码或密码摘要。
- 未知账号与已知账号错误密码采用不会形成明显账号枚举信号的校验路径。
- 自动化测试使用专用测试凭证，测试报告和快照不打印凭证内容。

## 2. 会话保持与退出

### US-S2-SESSION-01 刷新后恢复登录态（Must）

**用户故事：** 作为已登录员工，我希望刷新页面或在同一浏览器会话打开新标签页后继续工作，以免无故重复登录。

**所属 Feature：** F-S2-02 会话保持与退出。

**关联需求：** S2-SESSION-01、S2-SESSION-02、S2-SEC-03。

**验收标准：**

- 应用启动时先向后端确认当前会话，再决定渲染业务页面或登录页。
- 会话确认期间显示加载状态，页面不短暂展示未授权菜单或内容。
- 有效会话返回账号 ID、显示名称和角色等必要信息，不返回密码摘要或会话标识。
- 刷新授权页面或在同一浏览器会话打开新标签页时恢复当前用户并保留有权目标地址。
- 会话凭证由 `HttpOnly` Cookie 承载，不写入 localStorage、sessionStorage、URL 或可被 JavaScript 读取的状态。
- Cookie 的 `SameSite`、`Secure` 与跨站请求防护符合 PRD 的环境规则。
- 当前身份接口在未登录或会话无效时返回 401，不生成新的已登录会话。

### US-S2-SESSION-02 会话过期或账号停用后重新登录（Must）

**用户故事：** 作为门店员工，我希望会话失效时得到明确提示并安全返回登录页，以便知道需要重新验证身份。

**所属 Feature：** F-S2-02 会话保持与退出。

**关联需求：** S2-SESSION-03、S2-SESSION-05、S2-SESSION-06。

**验收标准：**

- 会话达到评审确认的空闲时限或绝对时限后，下一次受保护请求返回 401 且不读取或修改业务数据。
- 账号在会话期间变为停用时，下一次受保护请求使会话失效并返回 401。
- 前端收到会话失效响应后清除内存中的用户与权限状态，进入登录页并显示一次“登录已过期，请重新登录”。
- 多个并发请求同时返回会话失效时，只触发一次一致的退出流程，不重复堆叠提示。
- 重新登录后，仅当原目标为安全站内地址且当前角色有权时返回原目标。
- 页面明确不承诺保留未提交表单或交易草稿，不误导用户认为数据已保存。
- 服务异常或断网不会被错误显示为“账号或密码错误”。

### US-S2-SESSION-03 员工主动退出（Must）

**用户故事：** 作为已登录员工，我希望退出当前账号，以免共享设备上的其他人继续使用我的权限。

**所属 Feature：** F-S2-02 会话保持与退出。

**关联需求：** AUTH-01、S2-SESSION-04、S2-SEC-03、S2-SEC-05。

**验收标准：**

- 全局账号区域展示当前员工显示名称、角色名称和可操作的退出入口。
- 退出请求使用有跨站请求防护的非 GET 操作。
- 退出成功后服务端撤销当前会话，浏览器清除会话 Cookie，前端清除用户与权限状态并进入登录页。
- 退出后通过浏览器后退、刷新或重放旧 Cookie 均不能访问受保护页面或接口。
- 重复退出保持幂等，不产生 500 或恢复已失效会话。
- 后端暂时不可达时页面不假装退出成功；用户获得可理解提示，恢复后可重试。
- 退出响应和日志不包含会话 ID 或 Cookie 内容。

## 3. 角色化访问控制

### US-S2-AUTHZ-01 未登录用户访问受保护页面（Must）

**用户故事：** 作为未登录访问者，我希望被引导到登录页，以便验证身份后继续访问有权页面。

**所属 Feature：** F-S2-03 角色化访问控制。

**关联需求：** AUTH-02、SYS-03、S2-AUTHZ-01、S2-AUTHZ-06。

**验收标准：**

- `/pos`、`/orders`、`/products`、`/dashboard` 及其子路由默认要求登录。
- 未登录直接访问受保护路由时进入 `/login`，且页面不渲染受保护内容。
- 系统只保存规范化的站内相对返回地址，不接受协议、主机、脚本或其他外部目标。
- 登录成功后，有权目标可恢复；无权、无效或不存在目标回到角色默认页。
- 已登录访问不存在路由时仍显示 404，不把不存在页面一律解释为无权限。

### US-S2-AUTHZ-02 按角色查看和访问页面（Must）

**用户故事：** 作为收银员或管理员，我希望只看到适合自己职责的入口，以便快速进入工作区并避免误操作。

**所属 Feature：** F-S2-03 角色化访问控制。

**关联需求：** AUTH-02、S2-AUTHZ-02、S2-AUTHZ-03。

**验收标准：**

- 收银员导航展示 POS 和订单，不展示商品与经营看板。
- 管理员导航展示 POS、订单、商品与经营看板。
- 收银员直接访问 `/products` 或 `/dashboard` 时显示 403 和返回 `/pos` 的动作，不渲染页面业务内容。
- 管理员可直接访问四个业务模块入口。
- 导航在刷新、会话恢复和角色信息加载完成后保持一致，不短暂显示无权菜单。
- 权限信息未知时按未授权处理，不使用陈旧客户端角色放行页面。
- 页面隐藏只是体验层控制，不作为后端接口授权证据。

### US-S2-AUTHZ-03 后端独立执行接口权限（Must）

**用户故事：** 作为产品负责人，我希望后端独立校验每个请求的身份和角色，以便绕过前端也无法读取或修改无权数据。

**所属 Feature：** F-S2-03 角色化访问控制。

**关联需求：** AUTH-02、SYS-03、S2-AUTHZ-04、S2-AUTHZ-05、S2-SEC-06。

**验收标准：**

- 除登录、批准的健康检查及必要认证入口外，业务接口默认要求有效会话。
- 未登录或无效会话调用受保护接口返回 HTTP 401 和稳定业务码，不执行数据读取或变更。
- 已登录但角色不足时返回 HTTP 403 和独立稳定业务码，不执行数据读取或变更。
- `CASHIER` 可访问收银员允许接口；`ADMIN` 具备收银员权限并可访问管理员接口。
- 新增业务接口若未声明权限规则则默认拒绝，而不是默认公开。
- 直接构造 URL、修改前端状态、伪造角色字段或重复旧请求均不能提升权限。
- 401、403 响应保持统一 API 结构并包含 `traceId`，不返回内部授权规则或敏感上下文。

## 4. 初始化账号

### US-S2-ACCOUNT-01 可重复初始化最小账号集（Must）

**用户故事：** 作为测试或部署维护人员，我希望新环境可靠获得收银员和管理员账号，以便无需手工改库即可完成登录验收。

**所属 Feature：** F-S2-04 安全初始化账号。

**关联需求：** AUTH-03、S2-ACCOUNT-01 至 S2-ACCOUNT-04。

**验收标准：**

- 非生产验收环境至少存在一个 `ACTIVE` 收银员账号和一个 `ACTIVE` 管理员账号。
- 两类账号分别关联正确角色；管理员继承收银员业务权限由后续授权 Story 验收。
- 初始化仅写入密码摘要；仓库、迁移、API、日志和文档不包含生产可用明文密码。
- 生产初始凭证来自评审批准的受控部署渠道，缺少必要 Secret 时失败关闭且不创建弱默认账号。
- 初始化过程可重复执行：不重复创建角色或账号，不覆盖已有密码、状态或角色变更。
- 空库迁移和重复启动均有数据库集成测试。
- 停用测试账号后重复初始化仍保持停用，不恢复其密码、状态或角色；停用账号登录的统一失败反馈由 `US-S2-AUTH-02` 验收。

## 5. 安全事件与追踪

### US-S2-AUDIT-01 追踪认证与权限事件（Must）

**用户故事：** 作为研发和系统维护人员，我希望追踪认证与权限事件，以便定位异常而不暴露员工凭证。

**所属 Feature：** F-S2-05 可追踪的认证安全事件。

**关联需求：** SYS-02、S2-SEC-02、S2-SEC-04 至 S2-SEC-06。

**验收标准：**

- 登录成功、登录失败、退出、会话过期/失效、账号停用失效、频率限制和权限拒绝均产生结构化安全事件。
- 每条事件至少包含事件类型、结果、服务器时间、`traceId` 和必要的最小请求上下文。
- 能确认身份时可记录稳定账号 ID；登录失败不得通过日志向普通读者泄露账号是否存在。
- 日志不记录密码、密码摘要、会话 ID、Cookie、完整请求头或完整认证请求体。
- 401、403、429 可通过响应 `traceId` 与对应日志关联。
- 可预期认证失败不打印异常堆栈；未知系统异常在服务端保留必要堆栈但响应不暴露。
- 自动化测试或日志抽查覆盖每类事件，并包含敏感字段不存在的断言或检查记录。
