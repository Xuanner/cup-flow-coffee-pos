## 1. Feature 拆分原则

Feature 描述用户可感知且可整体验收的业务能力，不使用前端、后端、数据库等技术层作为 Feature。实现按 `TASKS.md` 的依赖与 Ready 状态执行。

| Feature | 名称 | 用户价值 | 优先级 | 关联 PRD |
| --- | --- | --- | --- | --- |
| F-S2-01 | 安全登录 | 员工可使用预置身份进入系统，失败时获得安全、可恢复的反馈 | Must | S2-AUTH-01 至 05、S2-SEC-01、02、04、06 |
| F-S2-02 | 会话保持与退出 | 员工刷新后可继续工作，并能主动或因过期安全结束会话 | Must | S2-SESSION-01 至 06、S2-SEC-03 至 06 |
| F-S2-03 | 角色化访问控制 | 收银员和管理员只看到并访问有权使用的页面和接口 | Must | S2-AUTHZ-01 至 06 |

## 3. Feature 说明

### F-S2-01 安全登录

**目标用户：** 收银员、管理员。

**价值假设：** 员工能在高频门店环境中快速建立可信身份，且错误反馈不会泄露账号状态或让用户无从恢复。

**能力边界：**

- 账号和密码登录。
- 表单校验、显示/隐藏密码、提交状态与失败恢复。
- 有效、停用、不存在账号及错误密码处理。
- 登录频率限制。
- 登录成功后的安全站内跳转。
- 不包含注册、找回密码、修改密码或 MFA。

**完成条件：**

- `US-S2-AUTH-01`、`US-S2-AUTH-02`、`US-S2-SEC-01` 全部验收通过。
- 收银员和管理员均可使用测试环境预置账号登录。
- 失败反馈、HTTP/业务错误码与安全日志保持一致。

**依赖：** F-S2-04；统一 API 与错误处理基础。

### F-S2-02 会话保持与退出

**目标用户：** 已登录员工。

**价值假设：** 员工刷新或打开新标签页时无需重复登录，但离席、退出、账号停用或超时后不会继续保留权限。

**能力边界：**

- 服务端可撤销会话与当前身份查询。
- 同一浏览器会话内恢复。
- 空闲过期、绝对过期、账号停用失效。
- 主动退出和旧会话复用拦截。
- 不包含记住登录、设备管理或远程下线。

**完成条件：**

- `US-S2-SESSION-01` 至 `US-S2-SESSION-03` 全部验收通过。
- 退出、过期和停用后的旧会话均无法读取受保护资源。
- 会话凭证不可被浏览器脚本读取，认证状态恢复期间无受保护内容闪现。

**依赖：** F-S2-01、F-S2-04。

### F-S2-03 角色化访问控制

**目标用户：** 收银员、管理员；后续业务模块开发者。

**价值假设：** 用户只接触与角色相关的入口，且即使绕过前端直接访问地址或接口也无法越权。

**能力边界：**

- 全局受保护路由。
- 按角色显示业务导航。
- 未登录 401 与无权限 403 的区分。
- 后端业务接口默认拒绝及显式角色规则。
- 站内返回地址验证。
- 不包含自定义角色或权限配置界面。

**完成条件：**

- `US-S2-AUTHZ-01`、`US-S2-AUTHZ-02`、`US-S2-AUTHZ-03` 全部验收通过。
- PRD 角色矩阵的页面与接口正向、反向用例全部通过。
- 后续模块可通过统一入口声明 `CASHIER` 或 `ADMIN` 访问规则。

**依赖：** F-S2-02。

### F-S2-04 安全初始化账号

**目标用户：** 测试验收人员、部署维护人员、门店首批员工。

**价值假设：** 新环境无需手工修改数据库即可获得最小可用身份，同时避免把默认明文密码固化在仓库或生产环境。

**能力边界：**

- 收银员与管理员最小账号集。
- 幂等初始化。
- 强密码摘要与环境化凭证来源。
- 停用状态参与登录校验。
- 不包含账号管理 UI 与密码生命周期管理。

**完成条件：**

- `US-S2-ACCOUNT-01` 验收通过。
- 空库初始化与重复启动测试通过。
- 仓库、接口与日志敏感信息检查通过。

**依赖：** Sprint 1 身份基础表与 Flyway 规则。

### F-S2-05 可追踪的认证安全事件

**目标用户：** 研发、测试与系统维护人员。

**价值假设：** 团队可以用 `traceId` 判断认证与权限失败发生在哪里，同时攻击者无法从响应或日志获得凭证与账号状态。

**能力边界：**

- 登录成功/失败、退出、会话失效和权限拒绝事件。
- 统一 401、403、429 响应。
- 凭证脱敏与最小上下文。
- 不包含安全运营后台、告警平台和长期审计报表。

**完成条件：**

- `US-S2-AUDIT-01` 验收通过。
- 每类事件均有自动化或人工验证证据。
- 日志抽查确认无密码、密码摘要、会话标识和 Cookie。

**依赖：** F-S2-01 至 F-S2-03；Sprint 1 `traceId` 与统一错误模型。

## 6. Feature 评审检查

- 非目标未以“技术预留”为由进入实现范围。
- 第 5 节追踪关系与 `USER_STORIES.md` 保持一致。
- 本文件、PRD、User Stories、API 契约和测试策略均已升级为 v1.0；后续变更须同步维护追踪关系。
