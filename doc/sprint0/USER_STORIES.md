# Cup Flow Coffee POS 第一阶段用户故事

本文档只覆盖第一阶段核心功能。优先级采用 Must、Should；故事点由研发团队完成技术拆分后估算。

## 1. 登录

### US-AUTH-01 员工登录（Must）

**用户故事：** 作为门店员工，我希望使用账号和密码登录，以便进入自己有权使用的功能。

**关联需求：** AUTH-01、AUTH-02、AUTH-03

**验收标准：**

- 有效且启用的账号可以登录。
- 收银员登录后可访问 POS 和订单，管理员还可访问商品后台与经营看板。
- 密码错误、账号不存在或停用时不建立登录态，并显示统一提示。
- 未登录用户访问受保护页面时被引导到登录页。
- 后端接口独立校验登录态和角色，不能只依赖前端隐藏入口。

### US-AUTH-02 员工退出（Must）

**用户故事：** 作为门店员工，我希望退出当前账号，以免其他人继续使用我的权限。

**关联需求：** AUTH-01

**验收标准：**

- 用户可从业务页面退出。
- 退出后当前登录态失效，再次访问受保护页面需重新登录。

## 2. POS 点单与收银

### US-POS-01 浏览和搜索商品（Must）

**用户故事：** 作为收银员，我希望按分类浏览并搜索商品，以便快速找到顾客需要的饮品。

**关联需求：** POS-01、POS-02

**验收标准：**

- 只展示已上架商品，并显示名称、基础价格和售罄状态。
- 切换分类后只展示该分类商品。
- 可按名称关键字搜索；无结果时显示空状态。
- 售罄商品不可加入购物车。

### US-POS-02 配置商品（Must）

**用户故事：** 作为收银员，我希望选择规格、温度、糖度和加料，以便准确记录顾客需求。

**关联需求：** POS-03

**验收标准：**

- 只显示当前商品支持且启用的选项。
- 必选项未选择时不能加入购物车，并指出缺少的选项。
- 选择带加价的规格或加料后，单价立即正确更新。
- 支持填写商品备注；相同商品的不同配置作为不同订单项。

### US-POS-03 管理购物车（Must）

**用户故事：** 作为收银员，我希望修改购物车，以便结算前纠正商品、数量和配置。

**关联需求：** POS-04、POS-05

**验收标准：**

- 可以修改数量和配置，删除单项或清空购物车。
- 数量只能是正整数，所有修改立即更新单项小计和总金额。
- 清空购物车前需二次确认。
- 空购物车不能创建订单或收款。

### US-PAY-01 创建订单（Must）

**用户故事：** 作为收银员，我希望从购物车创建订单，以便锁定本次交易明细并进入收款。

**关联需求：** POS-06、PAY-01、PAY-05

**验收标准：**

- 后端重新校验商品、选项、状态、价格和最终金额。
- 商品售罄、下架或价格变化时阻止直接提交，返回具体变化供收银员确认。
- 创建成功后得到唯一订单号，订单状态为待支付。
- 同一创建请求重复提交只生成一个订单。

### US-PAY-02 登记收款（Must）

**用户故事：** 作为收银员，我希望选择收款方式并确认收款，以便完成交易。

**关联需求：** PAY-02、PAY-03、PAY-04、PAY-05

**验收标准：**

- 可选择现金、微信、支付宝或银行卡。
- 非现金方式的实收金额等于应收金额。
- 收款成功后记录金额、方式、操作人和时间，订单变为已支付。
- 成功页显示订单号，并清空已结算购物车。
- 重复点击或请求重放不会产生第二条有效收款记录。

### US-PAY-03 现金找零（Should）

**用户故事：** 作为收银员，我希望输入顾客支付的现金，以便系统提示找零金额。

**关联需求：** PAY-06

**验收标准：**

- 现金实收不得小于应收金额。
- 系统显示的找零等于现金实收减去应收金额。
- 找零仅用于现场提示，不增加订单有效销售额。

## 3. 订单管理

### US-ORDER-01 查询订单（Must）

**用户故事：** 作为收银员，我希望查询订单及详情，以便处理顾客咨询和交易异常。

**关联需求：** ORDER-01、ORDER-02

**验收标准：**

- 可按完整订单号、单日日期和状态查询。
- 订单详情展示商品与配置快照、金额、收款方式、状态和关键时间。
- 未找到订单时显示明确空状态。

### US-ORDER-02 作废待支付订单（Must）

**用户故事：** 作为收银员，我希望作废不再需要的待支付订单，以免其被误收款。

**关联需求：** ORDER-03、ORDER-06

**验收标准：**

- 只有待支付订单可由收银员作废。
- 操作前二次确认；成功后订单不可再收款。
- 系统记录操作人、时间和状态变化。

### US-ORDER-03 完成订单（Must）

**用户故事：** 作为收银员，我希望将已经交付的订单标记为完成，以便区分进行中的交易。

**关联需求：** ORDER-04、ORDER-06

**验收标准：**

- 只有已支付订单可更新为已完成。
- 重复完成不会产生额外业务结果。
- 系统记录操作人和完成时间。

### US-ORDER-04 管理员取消订单（Must）

**用户故事：** 作为管理员，我希望取消异常的已支付或已完成订单，以便经营数据反映实际业务处理。

**关联需求：** ORDER-05、ORDER-06

**验收标准：**

- 只有管理员能执行取消。
- 取消前必须填写原因并二次确认。
- 取消后订单状态不可继续变化，金额从有效销售额中排除并计入取消金额。
- 系统不自动退款，并明确提示需按门店流程线下处理。
- 系统记录操作人、原因、时间和取消前状态。

## 4. 商品后台

### US-PRODUCT-01 管理商品分类（Must）

**用户故事：** 作为管理员，我希望维护商品分类，以便 POS 菜单结构清晰。

**关联需求：** PRODUCT-01

**验收标准：**

- 可新增、编辑、启用、停用分类并调整排序。
- 分类名称不能为空；同层有效分类名称不可重复。
- 停用分类后，其商品不在 POS 中展示，但历史订单不受影响。

### US-PRODUCT-02 管理商品（Must）

**用户故事：** 作为管理员，我希望维护商品和售价，以便 POS 使用当前菜单。

**关联需求：** PRODUCT-02、PRODUCT-06

**验收标准：**

- 可新增和编辑商品名称、分类、基础价格、描述及状态。
- 名称不能为空，基础价格不得为负数，无效数据不能保存。
- 下架商品不再出现在 POS，历史订单保留原商品与价格快照。

### US-PRODUCT-03 配置商品选项（Must）

**用户故事：** 作为管理员，我希望配置商品支持的选项，以便收银员只能选择有效的定制组合。

**关联需求：** PRODUCT-03

**验收标准：**

- 可配置杯型、温度、糖度和加料，包含名称、加价、是否必选和状态。
- 可为商品选择适用选项及默认值。
- 停用选项后不影响历史订单中的配置快照。

### US-PRODUCT-04 设置售罄（Must）

**用户故事：** 作为管理员，我希望快速设置商品售罄或恢复在售，以免出售暂时无法供应的商品。

**关联需求：** PRODUCT-04

**验收标准：**

- 可切换已上架商品的售罄状态。
- 状态变更后 POS 刷新数据即生效。
- 已加入购物车的商品随后售罄时，结算校验阻止下单。

### US-PRODUCT-05 筛选商品（Should）

**用户故事：** 作为管理员，我希望筛选商品，以便快速定位需要维护的记录。

**关联需求：** PRODUCT-05

**验收标准：**

- 可按名称、分类、上架状态和售罄状态筛选。
- 筛选条件可组合；无结果时显示空状态。

## 5. 简单经营看板

### US-DASH-01 查看经营概览（Must）

**用户故事：** 作为管理员，我希望查看当日经营指标，以便快速了解门店营业情况。

**关联需求：** DASH-01、DASH-02

**验收标准：**

- 默认按门店时区的当日数据展示。
- 展示有效销售额、有效订单数和客单价。
- 有效订单只包括已支付和已完成订单；客单价为有效销售额除以有效订单数。
- 单独展示取消订单数和取消金额。
- 看板汇总与相同条件下的订单明细一致。

### US-DASH-02 查看商品销量（Must）

**用户故事：** 作为管理员，我希望查看商品销量排行，以便了解当天畅销商品。

**关联需求：** DASH-03

**验收标准：**

- 按有效订单项数量从高到低展示 Top 10。
- 同名历史商品按商品 ID 统计，取消订单不计入销量。
- 无有效订单时显示空状态而不是错误数据。

### US-DASH-03 筛选日期和查看收款构成（Should）

**用户故事：** 作为管理员，我希望选择日期并查看收款方式构成，以便回顾某日经营情况。

**关联需求：** DASH-04、DASH-05

**验收标准：**

- 可选择一个自然日，不能选择未来日期。
- 指标和排行随日期同步更新。
- 展示各收款方式有效收款金额及占比，各项金额之和等于有效销售额。

## 6. 跨功能质量故事

### US-SYS-01 权限与审计（Must）

**用户故事：** 作为经营者，我希望敏感操作受权限保护且可追溯，以降低越权和误操作风险。

**关联需求：** SYS-02、SYS-03

**验收标准：**

- 页面和后端接口均校验权限。
- 无权限请求返回统一错误，不产生数据变更或越权数据泄露。
- 收款、订单作废/完成/取消、商品价格和状态变更均记录操作人、对象、结果和时间。

### US-SYS-02 可靠处理失败（Must）

**用户故事：** 作为系统用户，我希望操作失败时数据保持一致并得到明确反馈，以便安全重试。

**关联需求：** SYS-01、PAY-05、ORDER-06

**验收标准：**

- 失败时展示用户可理解的提示和可行的重试入口。
- 订单创建、收款和状态变化失败时不留下半完成数据。
- 重复点击、网络重试或并发操作不产生重复交易或非法状态。

## 7. 推荐实现顺序

1. US-AUTH-01、US-AUTH-02、US-SYS-01：登录、角色和权限基础。
2. US-PRODUCT-01 至 US-PRODUCT-04：建立可供 POS 使用的菜单数据。
3. US-POS-01 至 US-PAY-03：打通点单和收银。
4. US-ORDER-01 至 US-ORDER-04：补齐订单查询和异常处理。
5. US-DASH-01 至 US-DASH-03：实现简单经营看板。
6. US-SYS-02：贯穿各模块完成一致性、幂等和异常验证。
