# 后端与数据约定

## API

- 业务 API 前缀固定为 `/api/v1`；Actuator 不属于业务 API。
- HTTP 状态必须表达传输结果，业务响应同时提供稳定的 `code`。
- 响应字段统一为 `code`、`message`、`data`、`traceId`、`timestamp`。
- 参数错误、未登录、无权限、不存在、状态冲突和系统异常使用不同错误码。
- 未处理异常只在服务端记录，响应不得包含堆栈、SQL、凭证或内部地址。
- 请求接受安全格式的 `X-Request-Id`，否则生成新 ID；响应返回同名 Header。

## 模块与领域

- 使用模块化单体和轻量 DDD，不为简单 CRUD 强制制造聚合、工厂或领域服务。
- `ordering` 与 `payment` 是重点领域模块；金额、状态转换、快照和幂等规则进入领域模型。
- `reporting` 使用只读查询模型，不复用交易聚合承担报表查询。
- Repository 接口由领域或应用层定义，MyBatis Mapper 属于基础设施层。
- 事务边界放在应用服务；Controller 不直接访问 Mapper。

## 数据

- 主键使用 UUID，由应用生成；面向用户的订单号是独立业务字段。
- 人民币金额以 `BIGINT` 分存储和计算；接口在边界完成元/分转换，不使用浮点数。
- 时间列使用 `TIMESTAMPTZ`，系统时刻按 UTC 表达；门店自然日按 `Asia/Shanghai` 计算。
- 状态使用有名称的字符串及数据库 `CHECK` 约束，禁止使用 Java 枚举序号持久化。
- 可变交易数据预留 `version BIGINT` 进行乐观并发控制。
- 可维护记录使用 `created_at`、`created_by`、`updated_at`、`updated_by` 审计字段。
- 历史订单保存商品、选项和价格快照，不依靠当前商品表重建历史交易。
- 订单创建、收款和关键状态变化使用幂等键及唯一约束；具体行为在对应 Sprint 冻结。
- 已执行 Flyway 迁移不可修改，数据库结构不得通过手工步骤变更。

## 日志与敏感信息

- 日志输出结构化 JSON，并包含 `traceId`。
- 禁止记录密码、密码哈希、Token、Cookie、完整支付敏感信息和数据库凭证。
- 可预期业务失败记录必要上下文；未知异常记录堆栈并通过 trace ID 定位。
- 健康检查只返回状态，不返回数据库地址、账户、迁移 SQL 或内部组件细节。

## 认证会话

- 初始化账号密码使用 PBKDF2-HMAC-SHA256、600,000 次迭代、每个摘要独立的 16 字节随机盐和 256 位派生密钥；数据库保存包含算法与参数的自描述摘要，后续校验必须读取摘要自身参数。
- 初始化明文密码只从运行环境的 Secret 注入，长度限制为 12–128 字符；不得提供可直接登录的仓库默认值，也不得写入日志、异常、对象字符串或测试报告。
- 浏览器持有的原始不透明会话凭证只通过安全 Cookie 传输；数据库 `auth_sessions` 仅保存小写十六进制 SHA-256 摘要。
- 会话同时校验撤销状态、30 分钟空闲截止和登录后 8 小时绝对截止；过期判断以应用注入的 UTC 时钟为准。
- `last_activity_at`、`idle_expires_at`、`updated_at` 和 `version` 用于受保护请求后的活动刷新与乐观并发控制。
- 退出、超时、账号停用或会话替换通过 `revoked_at` 与受约束的 `revocation_reason` 记录。
- 过期或撤销会话在请求校验时立即失效，不等待物理删除。应用清理任务批量删除失效满 7 天的记录；相关到期和撤销索引由 V2 迁移提供。
- 清理任务失败不得导致过期会话重新有效；会话有效性始终由当前时间、撤销状态和账号状态共同决定。
